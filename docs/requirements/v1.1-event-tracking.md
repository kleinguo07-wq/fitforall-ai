# v1.1 功能埋点清单（待研发对齐）

本表列出 v1.1 功能直接需要的 8 项 P0 采集需求。4 项既有事件的复用与字段补充单独列出。待排期内容见[需求池埋点](../backlog/event-tracking.md)。

核对依据为 2026-09-01 至 2026-11-08 社体屏实际事件导出中的 51 个 eventID，以及竖屏 v1.0 代码快照。接入时以同一触发时机和同一业务含义判断是否复用。本期采集聚焦设备端视频屏保及 Follow Along 正式开始。

运动结算、管理后台、离线补传与个人最高分曝光的埋点暂缓。

D04 新内容沿用现有内容埋点和正式内容 ID。D03 的默认设置修正、详情视频循环、体态检测文案、认证后报告保留，以及 B02 心率入口显隐按各自验收项检查。

## 既有事件复用

- `PV_game_list`（D02）沿用人群页「更多」进入游戏列表的现有曝光。补充 `audience` 和 `entry_section`，分别记录热力健将（adult / sports_games）和跃动少年（youth / fun_exercise）。
- `click_game_item`（D02）沿用游戏卡片点击，保留现有 `item`、`catgrate`、`from`。水果达人和元气对决使用正式 `game_id`，并补充 `position`（1、2）以区分新增入口。
- `PV_face_flow`（D01）沿用进入人脸确认时的曝光，补充 `entry_source=screensaver`、`course_id` 和 `course_type`。统计范围为实际进入人脸确认的会话。
- `click_face_flow_result`（D01、D03-04）保留成功、访客和失败的既有口径，补充 `entry_source`、`network_mode`（online、offline）和双人 `participant_index`（1、2）。新增注册、离线待同步的结果映射待研发核对，按每位参与者记录，避免同一次结果双报。

## 统一口径

- 事件附端标识、应用版本、事件时间及脱敏会话标识；不上传姓名、手机号、人脸图像或特征等个人信息。
- 内容使用正式 course_id／game_id；页面文案或 Demo 键不能代替生产 ID。
- 双人身份结果按参与位置分别记录。
- 评审工具的推进时间、视频失败与空池控制不发送生产埋点。已有同义事件优先沿用，不同时上报两套事件。
