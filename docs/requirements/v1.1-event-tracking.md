# v1.1 功能埋点清单（待研发对齐）

本表只列本次新增或改变的行为。首页浏览、人群页浏览、既有训练列表和筛选等沿用现有 `0.0.1` 埋点，不重复定义。`版本号` 暂按产品需求版本填写 `v1.1`，上线时由研发映射实际客户端版本。`PV_` 在页面或内容实际可见时发送一次；`click_` 只记录真实用户点击／滑动；`result_` 由业务结算或配置保存结果产生，不由页面文案推断。

2026-10-12 最新确认：除签到与里程碑外的全部需求为 P0，签到与里程碑为 P1。大屏首页不再上报签到入口点击；签到移至大屏“我的数据”，报告保留签到记录入口；里程碑曝光与点击仅来自小程序。新增 4 个体能单项及易筋经复用既有课程曝光、开始和结算事件，以正式内容 ID 区分。事件 8 改为 `click_mydata_checkin`，事件 16 改为 `click_training_report_checkin`；旧首页签到和报告里程碑点击事件不再在新版本发送，历史数据不改写。

P0 对应 D01 视频屏保、D02 趣运动项目同步、D03 设置默认值、D04 老年内容扩充及 B01／B02 后台需求；P1 对应 D05–D08 签到流程及 M01／M02 小程序里程碑。页面编号和 eventID 分开管理，本次重排不修改历史 eventID。

系统默认与自定义共用体能、AI 跟练、趣味运动清单；趣味运动为切水果、节奏跳跃、顺序摸球、拳脚快打。配置方式沿用 recommended／fixed 属性值，分别表示系统默认／自定义；已移除人群筛选。D03 的默认设置自动初始化、封面制作和飞书链接属于配置／交付要求，不新增用户点击事件。

## 统一口径

- 设备、后台、小程序事件需要带端标识、应用版本、事件时间及匿名会话标识；场地和设备标识沿用现有合规公共参数，表中不重复占列。不要在埋点参数中放姓名、手机号、人脸原图、特征向量等个人信息。
- 用 `course_id`／`game_id` 做稳定内容标识，不依赖可变的展示文案。`sessionId` 用于服务端结算与去重；分析平台如需关联，使用脱敏会话标识。业务日由服务端按 `Asia/Shanghai` 的运动结束时间确定。
- 客户端的点击、浏览与服务端的有效运动、签到、累计、奖牌达成分别统计。离线记录在服务端确认前只算待同步，补传成功后同一会话不得重复结算。
- 本轮评审 Demo 右侧“推进 10 秒”“模拟下一天”“已签到切换”“视频失败”“空池”“重放报告”“里程碑 +1/+10/+100/归零”等都是评审控制，**不进入正式产品用户埋点**。
- 上线前需和既有埋点字典核对事件重名，并补齐后端实际课程 ID、游戏 ID、埋点 SDK 的公共字段和上报时机；同义旧事件优先复用，不并行上报两个同义事件。

- 同一次页面展示刷新不重复发送入口曝光。P0 的站位、身份、开始和结算事件保留同一 eventID；签到来源随 P1 启用，用 entry_source 区分，不同时发送一条“普通事件”和一条“签到事件”。
- 屏保进入后清理身份，退出回首页；复用既有首页 PV，不新增恢复原页面的事件。所有内容 ID 使用正式平台标识，演示中的 demo-* 键不得发送到生产埋点。
